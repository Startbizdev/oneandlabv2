# Matrice fonctionnelle mobile

Une entrée par route : actions UI → service mobile → endpoint backend → contrôles. Propriétaire : agent QA de la refonte premium.

## Méthode (phase 1, statique — 2026-10-01)

- Script `%TEMP%\cary-qa\trace.cjs` (hors repo) : fermeture d'imports de chaque route `apps/mobile/app/**`, puis **au niveau symbole** pour les services (`src/**/api/*.ts`, `lib/uploads`, `packages/shared-api`) : seuls les appels des fonctions réellement importées sont comptés.
- Résolution backend en émulant `backend/index.php` (routeur réel de `php -S` en local) ; contrôles relevés dans chaque fichier : `AuthMiddleware->handle()`, `RoleMiddleware->handle($user, [...])` de premier niveau, helpers `*_require_*()`, classes `*Access/*Gate/*Policy`, filtre `$user['user_id']`.
- Limites : un composant partagé gardé par rôle côté UI apparaît pour tous les rôles qui l'importent ; un module de hooks importé pour une constante fait remonter ses fetchs. Ces artefacts ont été vérifiés à la main (voir anomalies). Colonne « Vérifié » : [x] = tracé statiquement jusqu'au backend ; la validation runtime se fait en phase 2 (captures).
- Légende contrôles : `require_*` = helper d'auth+rôle du domaine ; liste de rôles = `RoleMiddleware` global ; `*Access/*Policy` = contrôle de propriété ; « auth + filtre user_id » = requêtes restreintes à l'utilisateur connecté.
